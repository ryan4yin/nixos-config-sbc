# Domain docs

This repository has one domain context.

## Before exploring

Read the root `GLOSSARY.md` and ADRs in `docs/adr/` relevant to the topic. If either is absent,
proceed silently; create domain documents only when terms or decisions are resolved.

## Vocabulary

Use the glossary's terms in issues, proposals, hypotheses and tests. When terminology is missing or
ambiguous, resolve it through domain-modeling.

## Decisions

Surface conflicts with an existing ADR before proposing a change. Do not silently override an
accepted decision.
